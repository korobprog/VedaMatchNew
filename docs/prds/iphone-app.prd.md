# VedaMatch для iPhone без App Store

Документ требований. Отвечает на вопросы «что должно быть» и «зачем»; «как» —
в плане реализации (`/plan`). Составлен 17 сентября 2026 по итогам обсуждения,
самодостаточен: его можно читать на другой машине без контекста беседы.

## Контекст

- У портала есть нативное приложение **для Android** — `apps/mobile`
  (Expo / React Native): Чаты, Звонки, Люди, Общины, вкладка «Сервисы».
  Вход тем же аккаунтом, что на сайте; пуши FCM; звонки с системным экраном.
- На iPhone участники сегодня получают только **PWA** сайта `vedamatch.ru` /
  `vedamatch.com`: интерфейс всего портала, тяжелее и медленнее приложения.
- Нативное приложение для iPhone требует аккаунта Apple Developer ($99 в год).
  **Владелец от платного аккаунта отказался.** Бесплатная подпись (Personal
  Team, AltStore) живёт 7 дней и не даёт пушей — для участников не годится.
- Разведка 17 сентября 2026 (ветка `spike/mobile-web`): `apps/mobile`
  собирается для браузера (`expo export --platform web`). Все пять вкладок,
  переписка и отправка сообщения работают. JS — 2,8 МБ, ~520 КБ brotli.
  Понадобились веб-версии пяти модулей (звонки Android, FCM, хранилище входа,
  аудиомаршруты, фоновые задачи) — нативная сборка не изменилась,
  473 теста проходят.
- На сервере уже есть: таблица способов входа `UserIdentity`
  (`google`, `vk`, `yandex`, `email`), cookie сессии на домене `.vedamatch.com`
  (`apps/api/src/modules/auth/contour.ts`), вход приложения по PKCE.
  **Привязки второго способа входа из настроек нет** — `identity.service.ts`
  только ссылается на неё в тексте ошибки.

## Решение

Вместо нативного приложения — **веб-сборка того же `apps/mobile`**, доступная
двумя путями:

1. **`ios.vedamatch.com`** — отдельный поддомен, ставится на экран «Домой»
   как PWA. Ходит только в `api.vedamatch.com` (контур `com`).
2. **Мини-приложение Telegram** — тот же адрес открывается из бота VedaMatch
   ссылкой `t.me/<бот>/app`. Вход — через Telegram, без пароля.

Уведомления о сообщениях и звонках — **сообщениями от бота**: на iPhone они
доходят надёжнее, чем веб-пуши, и не зависят от того, установлено ли что-то.

Один код на Android-приложение, веб-версию и мини-приложение: если аккаунт
Apple когда-нибудь появится, та же кодовая база станет нативным приложением.

## Проблема

Участники VedaMatch с iPhone пользуются порталом через PWA всего сайта: это
медленнее и беднее Android-приложения, уведомления ненадёжны, звонки
неудобны. Владельцы iPhone — второй сорт аудитории: реже возвращаются и не
могут полноценно пользоваться связью (чаты, звонки), которая и есть ядро
мобильного продукта.

## Свидетельства

- Наблюдение владельца: PWA на iPhone «не такой быстрый и функциональный,
  как натив», пуши работают, «но хотелось бы лучше».
- Зафиксированы тормоза веб-колоды Union на Android (убирали
  backdrop-filter) — тяжёлый веб на телефоне упирается в потолок.
- Разведка: интерфейс приложения в браузере работает без переделки.
- **Допущение — нужна проверка**: веб-сборка приложения быстрее PWA сайта на
  iPhone. Проверить замером на одном устройстве до запуска.
- **Допущение — нужна проверка**: доля iPhone среди участников и доля
  участников, у которых есть Telegram. Проверить по аналитике веба.

## Пользователи

- **Основной**: участник VedaMatch с iPhone, который переписывается и звонит.
  Триггер: пришло сообщение — хочет ответить так же быстро, как в Telegram.
- **Второй**: человек, который пришёл из Telegram (ссылка в чате общины,
  канале) и хочет войти, не заводя пароль и не вспоминая почту.
- **Третий**: владелец Android без APK — та же веб-версия работает и у него.
- **Не для**: iPad и компьютеры (не оптимизируем); платные функции внутри
  мини-приложения (Telegram требует оплату цифрового только в Stars —
  монетизация отдельным документом).

## Гипотеза

Мы верим, что **веб-версия приложения на `ios.vedamatch.com` и в Telegram, с
входом через Telegram и уведомлениями от бота**, **уравняет владельцев iPhone
с владельцами Android в переписке и уведомлениях** для **участников,
общающихся с телефона**. Мы поймём, что правы, когда **не менее 70 %
открывших ссылку дойдут до списка чатов, а недельное удержание будет не ниже,
чем у Android-приложения**.

## Метрики успеха

Целевые числа — предложение; уточняются после первого замера.

| Метрика | Цель | Как измерять |
|---|---|---|
| Вход по ссылке | ≥ 70 % открывших ссылку видят список чатов; вход через Telegram — одно касание | Воронка сервера: открытие → вход → список чатов |
| Холодная загрузка до списка чатов | ≤ 2,5 с на iPhone SE (2020) / iPhone 11 по 4G, повторная ≤ 1 с | Замер на эталонном устройстве, 5 запусков; сравнение с PWA сайта |
| Плавность списка и переписки | без заметных рывков, просадок ниже 50 к/с ≤ 2 % кадров | Web Inspector Safari на эталонном устройстве |
| Открытие переписки | ≤ 400 мс от тапа до сообщений | Web Inspector |
| Уведомление от бота | ≥ 95 % доставлены ≤ 10 с после сообщения | Сверка отправленного сервером с журналом Bot API |
| Привязка способов входа | Вход любым привязанным способом ведёт в тот же аккаунт | Ручной сценарий приёмки |
| Удержание 7 дней | Не ниже Android-приложения | Аналитика сервера по источнику (`ios`, `telegram`, `android`) |

### Как считать метрики

Источник входа (сайт / веб-версия `ios.vedamatch.com` / Telegram / Android)
пишется в `LoginAudit.client` при каждом входе (`AuthService.completeLogin`,
маппинг — `apps/api/src/modules/auth/login-client.ts`). Воронка «Вход по
ссылке» и «Удержание 7 дней» из таблицы выше читаются готовыми в админке:
`/admin` → раздел «Входы по источникам» — входы и уникальные люди за 7 и 30
дней и доля вернувшихся через 7+ дней по каждому источнику
(`GET /admin/stats/portal`, поле `logins`). Отдельная аналитика или ручные
SQL-запросы не нужны.

## Требования

### Обязательные

1. **Одна кодовая база**: веб-версия — сборка `apps/mobile`, без второго
   интерфейса. Нативная сборка Android не меняется.
2. **`ios.vedamatch.com`** раздаёт веб-сборку; API — `api.vedamatch.com`.
   Ставится на экран «Домой» (манифест, иконки, service worker).
3. **Вход на `ios.vedamatch.com`** — Google и Яндекс; сессия — httpOnly
   cookie на `.vedamatch.com`, общая с `vedamatch.com`. Токены в
   `localStorage` не хранятся.
4. **Бот VedaMatch и мини-приложение Telegram**: тот же адрес открывается
   внутри Telegram; интерфейс учитывает оболочку (кнопка «Назад», тема,
   безопасные зоны).
5. **Вход через Telegram**: сервер проверяет подпись `initData` ключом бота
   и находит или заводит аккаунт через `UserIdentity` с провайдером
   `telegram`. Работает и внутри мини-приложения, и виджетом входа на сайте.
6. **Привязка способов входа в профиле**: список привязанных способов,
   «Привязать» (Google, Яндекс, Telegram, почта с паролем) и «Отвязать».
   Только живой сессией; последний способ отвязать нельзя; способ, уже
   привязанный к другому аккаунту, — отказ с понятным текстом. Совпадение
   почты по-прежнему аккаунты **не** связывает.
7. **Уведомления через бота**: участник подключает бота (из мини-приложения
   автоматически, с сайта — кнопкой), получает сообщения о новых сообщениях
   и входящих звонках со ссылкой в переписку; отключается в настройках.
   Промо-рассылки — только по отдельному согласию.
8. **Звонки** в веб-версии работают, пока она открыта; входящий при закрытой
   версии — сообщение от бота «вам звонят» со ссылкой.
9. Светлая и тёмная тема, системный размер шрифта, VoiceOver на основных
   экранах; тексты на русском и английском, как на сайте.

### Желательные

- Деление JS по вкладкам (первая загрузка — только «Чаты»).
- Работа без сети: последний список чатов из кэша.
- Бейдж непрочитанных на иконке PWA.
- Вход через Telegram и привязка — и на основном сайте `vedamatch.ru` /
  `.com`, не только в веб-версии.

## Границы

**MVP** — веб-сборка на `ios.vedamatch.com` и в Telegram; вход через Google,
Яндекс и Telegram; привязка способов входа в профиле; уведомления о
сообщениях и звонках через бота; скорость по метрикам на эталонных iPhone.

**Вне границ**
- Нативное приложение для iPhone, TestFlight и App Store — нет аккаунта Apple.
- Контур `ru` для веб-версии (`ios.vedamatch.ru`) — только `com`.
- Нативные Union, Motivation, Market и прочие сервисы — остаются ссылками.
- Любая оплата внутри мини-приложения.
- Замена сайта или PWA сайта — они остаются.

## Открытые вопросы

- [x] **Почта у аккаунта из Telegram** — решено 17.09.2026: служебный адрес
      `tg-<id>@users.vedamatch.invalid`, настоящую почту просим в профиле.
- [x] **Где включать вход через Telegram** — только контур `com`.
- [ ] **Где хранятся данные участника из Telegram.** Способ входа гражданства
      не устанавливает — по правилу `identity.service.ts` неизвестное
      значит `ru`. Как это сочетается с тем, что веб-версия ходит только в
      `api.vedamatch.com`?
- [x] Бот — `@vedamatch_bot` (уже есть); токен — секрет API `TELEGRAM_BOT_TOKEN`.
- [ ] Адрес мини-приложения: Telegram требует HTTPS-домен, заданный в
      BotFather, — `ios.vedamatch.com` подходит для обоих путей или
      мини-приложению нужен свой адрес?
- [ ] Закрытая регистрация: пускать ли новых участников через Telegram так
      же, как через Google и Яндекс (`ResolveHooks.beforeCreate`)?
- [ ] Отвязка последнего «настоящего» способа: можно ли остаться только с
      Telegram?
- [ ] Какие iPhone есть для замеров (SE 2020 / iPhone 11)?
- [ ] Нужна ли аналитика экранов в веб-версии, чтобы мерить воронку.

## Риски

| Риск | Вероятность | Влияние | Смягчение |
|---|---|---|---|
| Telegram ограничат или заблокируют в России (звонки в нём уже ограничивали в 2025) | средняя | вход и уведомления части участников | Привязка Google/Яндекс/почты предлагается сразу после входа через Telegram; веб-пуши как запасной канал |
| Веб-сборка приложения на iPhone не быстрее PWA сайта | средняя | гипотеза не подтверждается | Замер в вехе 1 до вложений в вехи 2–7; деление JS по вкладкам |
| Захват аккаунта через привязку | низкая | потеря аккаунта | Привязка только живой сессией, подпись `initData` проверяется сервером, срок `auth_date` ограничен, совпадение почты не связывает |
| Safari выгружает свёрнутую веб-версию — звонок рвётся | высокая | звонки хуже, чем на Android | Честная граница: звонок — пока открыто; входящий — через бота |
| Поведение одного кода в Safari, Telegram и Android различается | высокая | мелкие дефекты | Приёмка каждой вехи на реальном iPhone в Safari и в Telegram |
| Бот упирается в лимиты Bot API при рассылке | низкая | задержка уведомлений | Очередь с ретраями по образцу `MotivationWorkerService` |

## Отклонённые варианты

- **Нативное приложение через App Store / TestFlight** — нужен платный
  аккаунт Apple; владелец отказался.
- **Бесплатная подпись (Personal Team, AltStore / SideStore)** — 7 дней,
  без пушей, сложная установка.
- **Партнёр-издатель** — в сторе чужое имя; оставлен как путь на будущее.
- **Облегчённый режим сайта Next.js на поддомене** — остаётся весь сайт,
  выигрыша в скорости мало, и это второй интерфейс рядом с приложением.
