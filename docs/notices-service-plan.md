# Сервис «Объявления» (`notices`)

Некоммерческая доска общины: отдам даром, нужны руки на переезд, еду в Маяпур —
могу отвезти, воскресная программа в 16:00. Вместе с ним заводится портальная
сущность **община** (ятра, храм, нама-хатта, клуб) — справочник, карта и
принадлежность человека к общине, видимая на всём портале.

Строится по [контракту сервисного модуля](./service-module-contract.md).
Образец изоляции — **только `market`** (`apps/api/src/modules/market/`):
`ContactsModule` импортирует `UsersModule`, `UnionModule` и `ModerationModule`
(`apps/api/src/modules/contacts/contacts.module.ts:11`) и потому эталоном не
является — у «Контактов» берём образец документа, модель приватности и
поисковый SQL, но не устройство модуля.

Главный риск сервиса не технический, а продуктовый: у портала уже есть **Рынок**,
где модель `MarketListing` прямо подписана «Объявление». Второй сервис с тем же
словом в названии превратится либо в дубль Рынка, либо в свалку. Поэтому граница
зафиксирована до начала работы.

## Принятые решения

1. **Строго некоммерческий.** Поля цены в модели нет вообще — не «необязательное»,
   а отсутствующее. Как только в объявлении появляются деньги, это Рынок.
   Отсутствие поля — единственная граница, которая держится сама.
2. **Slug `notices`, а не `announcements`.** Имя `Announcement` занято моделью
   новостей портала (`schema.prisma:1628`); совпадение префиксов в общей схеме
   стоило бы дороже, чем чуть менее очевидное слово в URL.
3. **Община — портальная инфраструктура, а не модель сервиса.** Принадлежность
   к ятре должна быть видна в профиле, в знакомствах и в справочнике, а не только
   внутри Объявлений. Модель, живущая внутри одного сервиса, немедленно
   обзавелась бы копиями в остальных. Решение требует правки контракта — см. ниже.
4. **Вид объявления — enum, рубрика — таблица.** Тот же принцип, что развёл
   `ContactsTag` и `ContactsAshram`: вид меняет форму и жизненный цикл (закрытый
   набор), рубрика — только полку в каталоге (растёт постоянно).
5. **Объявления протухают.** Доска, где просьбы годовой давности висят наравне
   со свежими, мертва. `expiresAt` по умолчанию 30 дней, продление одним нажатием.

## Границы: Объявления vs Рынок

|               | Рынок (`market`)                       | Объявления (`notices`)                        |
| ------------- | -------------------------------------- | --------------------------------------------- |
| Зачем         | обмен, где есть деньги                 | взаимопомощь и жизнь общины                    |
| Единица       | товар или услуга с ценой               | просьба, предложение, событие                  |
| Кто автор     | магазин (`MarketShop`)                 | человек или община                             |
| Чем кончается | заказ, оплата, отзыв о продавце        | отклик, договорённость, благодарность          |
| Цена          | обязательна                            | **поля нет**                                   |
| Срок жизни    | висит, пока не продано                 | протухает: `expiresAt`                         |
| Репутация     | рейтинг магазина, отзывы               | благодарности, без звёзд и среднего балла      |
| Каталог       | двухуровневый, фильтры на категориях   | одноуровневые рубрики + вид объявления         |

Если в интерфейсе Объявлений появляются цена, корзина или рейтинг продавца —
сервис уехал в Рынок.

### Дрейф в коммерцию

Доска взаимопомощи неизбежно притягивает «массаж 2000 ₽» и МЛМ.

- Чистый валидатор `notice-commerce-guard.ts` (по образцу
  `apps/api/src/modules/market/market-listing-validate.ts`) ищет ценовые маркеры
  и ставит `needsReview = true`, **не блокируя публикацию**: срабатывание на
  «отдам даром, забрать до 18:00» не должно молча съедать объявление.
- У модератора действие «перенести в Рынок»: статус `moved_to_market`, автору —
  уведомление со ссылкой `/market/sell?title=…&description=…`. Передача через
  query-параметры, а не чтением чужих таблиц: изоляция сохраняется.
- Третья открытая жалоба скрывает объявление — логика `crossesHideThreshold`
  из `market/report-threshold.ts` копируется в модуль, как требует контракт.

## Правка контракта

Пункт про read-only доступ к портальным таблицам сейчас говорит, что список
(`User`, `UserBlock`) исчерпывающий. Он расширяется:

> Наравне с `User` разрешено read-only читать `UserBlock` и `Community` /
> `CommunityMember`. Блокировка обязана действовать во всех сервисах сразу,
> а принадлежность к общине — сквозной признак человека: она видна в профиле,
> в знакомствах, в справочнике и в объявлениях, и живущая внутри одного сервиса
> копия немедленно разъехалась бы с остальными. Работа с общинами идёт через
> `CommunitiesModule` — портальную инфраструктуру наравне с `ModerationModule`, —
> а не через прямые запросы к таблицам. Список по-прежнему исчерпывающий:
> «оно же почти портальное» — не аргумент.

## Портальные модели: община

```prisma
// ===== Communities (portal) =====
enum CommunityKind         { yatra  temple  ashram  nama_hatta  farm
                             club  center  project }
enum CommunityStatus       { draft  pending  active  paused  archived
                             hidden_by_reports  removed_by_admin }
enum CommunityJoinPolicy   { open  request_approval  invite_only }
enum CommunityMemberRole   { owner  admin  moderator  member }
enum CommunityMemberStatus { pending  active  declined  left  removed }

model Community                  // slug, kind, name, описание, лого/обложка, гео,
                                 // timezone, joinPolicy, status, verifiedAt, счётчики
model CommunityMember            // role, status, title, isPrimary, isPublic, joinedAt
model CommunityOwnershipTransfer // передача владения с согласия принимающего
```

`moderator` заведён под делегированную модерацию Объявлений (этап E): скрыть
объявление своей общины, но не править саму общину. Без делегирования доска
не масштабируется — портальная администрация станет узким местом.

`isPrimary` определяет, какая из общин человека показывается значком в профиле.
Ровно одна на человека; частичный уникальный индекс Prisma выразить не умеет,
поэтому инвариант держит сервис и покрывает тест.

Гео продублировано скалярными колонками рядом с `location Json?` — ровно как у
`MarketShop`: JSON в Postgres не индексируется, а по городу идёт фильтр выдачи.
`address String?` есть: у храма адрес публичный, в отличие от дома человека.

**Кто заводит общину.** Не свободно: справочник ятр за месяц зарастает дублями
«Москва», «Москва ятра», «ятра г. Москва». Создание даёт `status: pending`,
портальный админ переводит в `active`, создатель сразу `owner`.
`verifiedAt` — отдельный, более сильный знак доверия.

**Владение.** Передача идёт через `CommunityOwnershipTransfer` с согласия
принимающего и сроком на ответ: односторонним присваиванием поля общину можно
было бы «подарить» человеку, который об этом не просил, и повесить на него
ответственность за модерацию. По принятии старый владелец становится `admin`.
Община без активного `owner` невозможна — проверка в сервисе, а не в схеме.

**Как это видят другие сервисы.** `CommunitiesModule` экспортирует
`CommunitiesService` с узким контрактом — `membershipsOf(userId)`,
`badgeFor(userId)`, `canPostAs(userId, communityId)`. Импортируется так же, как
`union` импортирует `ModerationModule`. Прямого чтения таблиц `Community*` из
чужих модулей нет.

## Модели сервиса

```prisma
// ===== Notices service =====
enum NoticeKind           { offer  request  event  info }
enum NoticeStatus         { draft  published  hidden_by_author  resolved  expired
                            moved_to_market  hidden_by_reports  removed_by_admin }
enum NoticePlacePrecision { exact  city }
enum NoticeAudience       { everyone  my_city  my_community }

model Notice             // объявление: автор всегда человек, община — необязательна
model NoticeRubric       // таксономия доски, системные приезжают сидом
model NoticeImage        // фото, копия MarketListingImage
model NoticeResponse     // отклик: pending / accepted / declined
model NoticeThanks       // благодарность вместо рейтинга
model NoticeAttendee     // «пойду» на событие
model NoticeFavorite
model NoticeSubscription // рубрика + город + община → пуш
model NoticeReport       // жалоба, копия MarketReport
```

`Notice.authorId` заполнен **всегда**, даже при публикации от имени общины:
за текстом стоит человек, и отвечает он. `communityId` необязателен и разрешён
только `owner`/`admin` — проверка через `CommunitiesService.canPostAs`.

Поля события: `startsAt`, `endsAt?`, `timeZone` (строка IANA), `venueName?`,
`address?`, `isOnline`, `onlineUrl?`, `recurrenceRule?`, `recurrenceUntil?`.
Время хранится в UTC отдельно от пояса: у онлайн-программы участники в разных
поясах, и «18:00» без пояса бессмысленно.

FK на `User` и `Community` разрешены, на модели других сервисов — запрещены.

### Протухание и повторы

`@nestjs/schedule` в репозитории нет: фоновая работа — воркер `OnModuleInit` +
`setInterval(...).unref()`, образец `motivation/motivation-worker.service.ts:45-61`
(там же опциональный Redis-лок против двойного выполнения на нескольких
инстансах) и `astro/transits/astro-transit-worker.service.ts:84`.

`NoticesWorkerService` тикает раз в пять минут: переводит просроченные в
`expired`, за три дня до срока спрашивает автора «продлить или закрыть?»,
материализует ближайшее вхождение повторяющегося события. Экадаши и праздники —
списком дат, а не правилом RRULE: лунный календарь правилом не выражается.

## Гео и карта

Радиус уже реализован ровно так, как нужно, — в
`apps/api/src/modules/contacts/contacts-search-query.ts`: грубая рамка плюс
точный гаверсинус, всё одним SQL-выражением, тесты в
`contacts-search-query.spec.ts:232`. Файл копируется в модуль и упрощается: у
Contacts координаты достаются из `User.homeLocation` через `jsonb_typeof`,
здесь они лежат скалярными колонками самой записи.

Оттуда же переносится главное правило: **выдача, `total` и фасеты строятся из
одного и того же `WHERE`**. Фильтрации после выборки нет нигде — она дырявит
пагинацию и разводит счётчики с лентой.

Геокодинг переиспользуется как есть: портальные `GET /geo/search` и
`GET /geo/reverse` в `apps/api/src/modules/users/geo.controller.ts`.

**Карта.** Leaflet + OSM, загрузка через динамический `import()` внутри
`useEffect` — модуль трогает `window` и ломает SSR. Образец
`components/contacts/contacts-map.tsx` копируется в
`components/notices/notices-map.tsx`. Отличие: Contacts кластеризует по городам,
здесь нужны настоящие точки — у храма адрес, у события площадка. `GET /notices/map?bbox=`
отдаёт точки, пока их в рамке меньше порога, и агрегаты по городам, когда больше;
фетч перезапускается на `moveend` с дебаунсом, лимит точек на ответ фиксирован.

**Приватность места.** Объявление человека по умолчанию `placePrecision: city`
и пинится в центроид города: доска не должна показывать, где человек живёт.
`exact` доступен общинам, храмам и событиям и требует явного подтверждения
в форме. Это же поле решает, отдаются ли координаты в DTO.

## Приватность и злоупотребления

| Дыра                             | Решение                                                                 |
| -------------------------------- | ----------------------------------------------------------------------- |
| Фильтрация после выборки         | всё в SQL, `total` и фасеты из того же `WHERE`                           |
| Домашний адрес по объявлению     | `placePrecision: city` по умолчанию, координаты в DTO только при `exact` |
| Сбор контактов пачкой            | контакты не в выдаче; связь через `NoticeResponse` → согласие            |
| Прямой URL скрытого объявления   | **404, не 403** — 403 подтверждает существование                         |
| Спам и МЛМ                       | нет полей цены, `notice-commerce-guard`, автоскрытие с трёх жалоб        |
| Дубли одного объявления          | лимит активных на автора, дедуп по заголовку + рубрике + городу          |
| Заблокированные пользователи     | read-only `UserBlock` и `hiddenUserIds` из `moderation`, исключать в SQL |
| Индексация поисковиками          | `noindex`, доступ только авторизованным                                  |
| Офлайн-встречи                   | памятка на карточке отклика, кнопка жалобы всегда на виду                |

Гостю лента не открыта, в отличие от Рынка: некоммерческая доска общины — это
внутренняя жизнь, а не витрина. Гость видит только правила и лендинг сервиса.

## API

Префикс маршрутов — slug сервиса; стиль контроллеров —
`apps/api/src/modules/market/market-listings.controller.ts`.

- `GET /notices` — лента с фильтрами и фасетами (`OptionalAuthGuard`, `@Throttle 120/60s`)
- `GET /notices/:id` · `POST /notices` · `PATCH /notices/:id` · `POST /notices/:id/status`
- `POST|DELETE /notices/:id/images` · `POST /notices/:id/images/reorder`
- `GET|POST /notices/:id/responses` · `POST /notices/responses/:id/respond`
- `POST /notices/:id/thanks` · `POST /notices/:id/favorite`
- `GET /notices/rubrics` · `GET /notices/map?bbox=`
- `GET /notices/events?from=&to=` · `GET /notices/events/:id/ics` · `POST /notices/:id/attend`
- `GET|POST|DELETE /notices/subscriptions`
- `POST /notices/:id/reports` · `GET /notices/admin/reports`

Общины — портальный префикс:

- `GET /communities` · `GET /communities/:slug` · `GET /communities/map?bbox=`
- `POST /communities` (→ `pending`) · `PATCH /communities/:id` · `POST /communities/:id/logo|cover`
- `GET /communities/me` · `POST /communities/:id/join`
- `POST /communities/:id/members/:userId/respond` · `DELETE /communities/:id/members/:userId`
- `POST /communities/:id/verify` (админ портала)

Frontend: `apps/web/src/app/notices/` и `apps/web/src/app/communities/`,
компоненты в `components/notices/` и `components/communities/`, клиенты
`lib/notices-api.ts` и `lib/communities-api.ts`, типы `packages/shared/src/notices.ts`
и `packages/shared/src/community.ts`. Выбор общины встраивается в
`components/profile-editor.tsx` рядом с блоком города.

## Что делает доску живой

В первой версии:

- **Явное закрытие просьбы.** Статус `resolved` и вопрос «получилось?» через
  неделю. Доска, где половина просьб протухла молча, мертва.
- **Благодарности вместо рейтинга.** У некоммерческой помощи нет продавца,
  которого оценивают звёздами: счётчик «спасибо» без среднего балла и без
  публичного антирейтинга.
- **Подписка «рубрика + город» с пушем.** Инфраструктура уже есть
  (`PushSubscription`, `NotificationPreference`, `NotificationItem`).
  Без неё доску открывают раз в месяц.
- **Объявление, привязанное к общине как к месту** — «на кухне у московской
  ятры». Страница общины получает живую ленту вместо пустой карточки.

Позже: календарь и `.ics`; повторяющиеся программы (воскресная, экадаши,
Гаура-пурнима, Картика); попутчики с маршрутом `from → to`; закрытая доска
служений ятры (`audience: my_community`); делегированная модерация админам
общин — единственный способ масштабировать доску без штата модераторов;
ретрансляция в Telegram-канал ятры.

Отвергнуто: карма с отрицательной частью (превращает помощь в соревнование);
комментарии под объявлениями (публичные споры на просьбе о помощи — вместо них
отклики); денежные сборы (отдельная тема с юридическими последствиями).

## Этапы

- **A. Портал — готово.** `Community` / `CommunityMember` /
  `CommunityOwnershipTransfer` с миграцией, модуль
  `apps/api/src/modules/communities/`, правка контракта, выбор общины в профиле,
  экран разбора заявок на `/admin/communities`. Запись `notices` в сиде со
  `status: 'coming_soon'`. Два правила, которые легко сломать «улучшением»:
  заявка в неподтверждённую общину отклоняется (иначе через вступление
  обходится премодерация), и владелец не выходит из общины, пока не передал её.
- **B. Ядро — готово.** 14 рубрик сидом (`prisma/notice-rubrics-data.js`),
  `Notice` + `NoticeRubric` + `NoticeImage` с миграцией, CRUD, лента с
  курсорной пагинацией и фильтрами, загрузка фото (копия
  `market-images.service.ts`), воркер протухания, страницы `/notices`,
  `/notices/new`, `/notices/[id]`, `/notices/my`, `/notices/rules`.
  Откликов ещё нет — связаться с автором пока нельзя, поэтому сервис остаётся
  `coming_soon` до этапа D.
- **D. Связь и модерация — готово.** `NoticeResponse` / `NoticeThanks` /
  `NoticeReport` с миграцией, отклики с раскрытием контактов по согласию,
  благодарности, жалобы с автоскрытием на третьей, `notice-commerce-guard`,
  очередь модератора на `/admin/notices`, страница «Мои отклики».
  Сервис переведён в `active`, число сервисов в пяти маркетинговых строках
  поднято до восьми, добавлена запись в `lib/service-content.ts`.
  Правило, которое легко сломать «улучшением»: контакты раскрываются
  **только** принятому отклику и только той стороне, которой предназначены —
  иначе доска становится способом собрать базу преданных.
- **C. Гео — готово.** Радиус (`radiusKm` + точка) через `notice-geo.ts`,
  `GET /notices/map` в двух режимах, страница `/notices/map` на Leaflet.
  Три решения, которые легко сломать «улучшением»:
  1. Радиус применяется **двумя шагами** — SQL с рамкой и гаверсинусом отдаёт
     id, они входят в общий `where`. Гаверсинус в билдер Prisma не выражается,
     а фильтровать после выборки нельзя: это дырявит курсорную пагинацию.
  2. Дельта долготы в рамке считается по краю, ближнему к полюсу, а не по
     центральной широте. В `contacts-search-query.ts` она берётся от центра —
     на городских радиусах разница незаметна, на больших это отрезает точки,
     которые в радиус попадают.
  3. Режим карты (точки или агрегаты) выбирает сервер: только он знает,
     сколько записей в рамке, и только так у клиента нет второй правды о том,
     сколько объектов в точке.
  Карта строится из того же `where`, что и лента, — числа сходятся, и
  закрытое объявление общины не утекает меткой.
- **E. События, подписки, делегирование — готово.**
  Повторы (`weekly`/`biweekly`/`monthly`/`ekadashi`) разворачиваются в
  приложении, `GET /notices/events`, экспорт `.ics`, подписки «рубрика /
  город / община» с уведомлениями, скрытие объявления администрацией общины.
  Четыре решения, которые легко сломать «улучшением»:
  1. Вхождения повторов **не хранятся строками**. Правка воскресной программы
     иначе стала бы правкой сотни записей.
  2. Шаг повтора считается в зоне события через `luxon` и **от исходной даты**,
     а не от предыдущего вхождения: иначе «программа в 18:00» уезжает на час
     после перевода часов, а «каждое 31-е» навсегда съезжает на 28-е.
  3. **Даты экадаши не выдуманы.** `ekadashi-dates.ts` намеренно пуст: лунный
     календарь зависит от места наблюдения, по нему постятся, и ошибка в дате
     — не косметика. Пока таблица пуста, повтор `ekadashi` отклоняется с
     внятным сообщением. Заполняется выгрузкой из календаря ятры.
  4. У доски **своя категория уведомлений** `notices`, а не переиспользование
     `market`: выключив коммерцию, человек не должен молча потерять доску.
  Порядок контроллеров в `notices.module.ts` значим — `@Get(':id')` перехватил
  бы `/notices/subscriptions`; менять порядок нельзя, не проверив маршруты.

## Открытые вопросы

1. **«Жильё и соседи».** Аренда за деньги формально Рынок, но поиск соседа и
   «пущу пожить на время фестиваля» — по духу доска общины. Предложение:
   оставить рубрику без сумм, аренду с ценой отправлять в Рынок.
2. **Полнотекстовый поиск.** `docs/prisma-raw-sql-objects.md` предупреждает:
   tsvector и `gin_trgm_ops` создаются сырым SQL, и `prisma migrate dev` пытается
   снести их на каждой миграции. На этапе B обойтись `ILIKE` по заголовку и не
   пополнять этот список; вернуться, если поиск окажется узким местом.
