# Union: авто-фильтр по полу для пользователей с высокой целью «Создание семьи»

## Проблема

В Union-знакомствах у каждого профиля есть набор целей (`UnionIntention`) с весами 0–100, сумма = 100. Один из типов — `family` («Создание семьи»). Сейчас лента рекомендаций не учитывает пол по умолчанию: явный фильтр по полу опционален, задаётся вручную во фронтовых фильтрах, и работает только в одну сторону (сужает то, что видит зритель, но не влияет на то, кому показывают его самого).

Для пользователей, чья цель — прежде всего создание семьи, разнополый мэтчинг обычно и есть искомый результат. Нужно, чтобы для таких пользователей подбор по умолчанию сужался до противоположного пола — в обе стороны (и в их ленте, и в чужих лентах относительно них), — но с возможностью полностью отключить это в настройках профиля.

## Область действия

Только модуль Union (`apps/api/src/modules/union/**`, `apps/web/src/components/union/**`). Общий `User.gender` и `UnionIntention` не меняются по структуре — используются как есть.

Ограничение применяется только к ленте рекомендаций (`GET /union/recommendations`, `union-profile.service.ts#getRecommendations`). Прямой просмотр анкеты по id (`GET /union/users/:id`) и уже установленные связи/чаты не блокируются — это осознанное решение, чтобы не ломать существующие контакты.

## Условие активации ограничения

Ограничение считается активным для пользователя U, если выполняются все три условия:
1. `U.gender` указан (не `null`);
2. вес интенции типа `family` в `UnionIntention` профиля U ≥ 50 (если интенция `family` не задана — вес считается 0, условие не выполняется);
3. `UnionProfile.disableFamilyGenderFilter === false` (тумблер отключения не включён).

Если хотя бы одно условие не выполняется (пол не указан, вес < 50, или пользователь явно отключил фильтр) — ограничение для этого пользователя не действует, лента и видимость профиля работают как сейчас, без изменений.

## Логика фильтрации

Ограничение — жёсткий гейт кандидатов, не влияет на скоринг совместимости в `UnionMatchingService`. Работает независимо для каждой стороны пары (не требует, чтобы у ОБОИХ была активна цель ≥50% — это осознанно отклонённый вариант):

Для пары «зритель V, кандидат C» кандидат C исключается из ленты V, если выполняется хотя бы одно:
- ограничение активно у V, и `C.gender` не противоположен `V.gender` (либо `C.gender` не указан — тогда тоже исключается, т.к. соответствие проверить нельзя);
- ограничение активно у C, и `V.gender` не противоположен `C.gender` (аналогично, если `V.gender` не указан — исключается).

Это добавляется как ещё одна проверка внутри существующего `matchesFilters()` (`union-profile.service.ts`), рядом с уже реализованным явным gender-фильтром из query-параметров. Оба фильтра независимы и комбинируются через AND (если задан явный `?gender=`, а также активно авто-ограничение — оба должны выполняться).

Для вычисления веса `family`-интенции при загрузке кандидатов и зрителя используется существующая связь `UnionProfile.intentions` (уже используется в `UnionMatchingService` для скоринга, доп. include не потребуется либо потребуется минимальное расширение select).

## Изменения в данных

Новое поле в `UnionProfile` (Prisma):
```
disableFamilyGenderFilter Boolean @default(false)
```
Требуется миграция. Поле по умолчанию `false` — то есть ограничение включено «по умолчанию», когда выполняются условия активации (это дефолт для НОВОГО тумблера, а не изменение поведения для всех — само ограничение и так применяется только когда family-вес ≥50%, так что для большинства существующих пользователей поведение не меняется).

Прокидка поля:
- `packages/shared/src/union.ts` — добавить в `UnionProfileDto` и `UnionProfileUpdateRequest`.
- `union-profile.service.ts` — читать/писать поле в upsert-обработчике профиля (по аналогии с `requestsFromVerifiedOnly`).

## UI

В `apps/web/src/components/union/union-profile-form.tsx`, рядом с существующими чекбоксами (`isActive`, `requestsFromVerifiedOnly`) — новый чекбокс:

> «Показывать мне анкеты всех полов, даже если моя цель «Создание семьи» ≥50%»

Не отмечен по умолчанию (т.е. `disableFamilyGenderFilter = false`, ограничение действует при выполнении условий). Текст поясняет пользователю, почему лента может сужаться, и даёт способ это отключить.

## Тестирование

- Юнит-тесты на новую проверку в `matchesFilters()` / `getRecommendations()`:
  - family-вес ≥50 и пол указан → кандидаты противоположного пола проходят, своего пола — нет;
  - family-вес <50 → фильтр не применяется;
  - пол не указан → фильтр не применяется, независимо от веса;
  - `disableFamilyGenderFilter = true` → фильтр не применяется, даже если вес ≥50 и пол указан;
  - односторонний случай: у зрителя ограничение неактивно, у кандидата активно и требует противоположный пол — кандидат всё равно должен быть исключён из ленты зрителя, если зритель не подходит по полу;
  - комбинация с явным `?gender=` фильтром — оба ограничения применяются одновременно (AND).
- Ручная проверка через `union-profile-form.tsx`: тумблер сохраняется и подгружается корректно.
