# Union: фокус-режим свайпов на мобильном

## Проблема

На мобильном экран «Знакомства» (`/union/recommendations`) по умолчанию
показывает колоду свайпов (`SwipeDeck`) внутри обычной страницы: сверху
глобальная шапка портала (лого, уведомления, тема, аватар — рендерится в
`apps/web/src/app/(portal)/layout.tsx`, общая для всех разделов), заголовок
раздела с кнопкой настроек (`UnionTopBar`), панель фильтров (свёрнута, но
полоска-переключатель видна), строка «Найдено: N. Страница X из Y.»,
переключатель «Списком/Свайпами», а снизу — таб-бар навигации
(`UnionTabBar`, `fixed`, `md:hidden`). Всё это конкурирует за внимание с
самой колодой, хотя свайпы — режим быстрого, одного за другим просмотра
анкет, где отвлекающие элементы не нужны.

## Область действия

Только `apps/web/src/components/union/recommendations-view.tsx`. Ни
`swipe-deck.tsx`, ни `apps/web/src/app/(portal)/layout.tsx`, ни
`union-top-bar.tsx`, ни `union-tabbar.tsx` не меняются — оверлей визуально
перекрывает их, не требуя координации с этими файлами.

Затрагивает только мобильный свайп-режим. Десктоп (`isMobile === false`)
не меняется: свайп-режим там остаётся как сейчас, инлайн внутри обычной
страницы.

## Решение

### Условие активации

`RecommendationsView` уже вычисляет `isMobile` через
`useSyncExternalStore(subscribeToMobileQuery, ...)` и хранит `mode: "grid"
| "swipe"`. Полноэкранный оверлей активен ровно когда `isMobile && mode ===
"swipe"` — назовём это условие `focusMode` в реализации.

### Разметка

Когда `focusMode` истинно, вместо инлайнового рендера `<SwipeDeck
items={items} />` рендерится:

```tsx
<div
  className="fixed inset-0 z-50 flex flex-col bg-bg-0 px-4"
  style={{
    paddingTop: "calc(env(safe-area-inset-top) + 0.75rem)",
    paddingBottom: "calc(env(safe-area-inset-bottom) + 0.75rem)",
  }}
>
  <button
    type="button"
    onClick={exitFocusMode}
    aria-label="Выйти из фокус-режима"
    className="mb-2 flex h-10 w-10 items-center justify-center rounded-xl glass border border-glass-brd text-text-1 transition hover:text-text-0"
  >
    <span aria-hidden="true">✕</span>
  </button>
  <div className="flex flex-1 items-center justify-center overflow-y-auto">
    <SwipeDeck items={items} />
  </div>
</div>
```

`SwipeDeck` рендерится без изменений своего кода — просто в другом
родителе. Его собственный счётчик «N из M» остаётся частью его вывода и
окажется под верхней полосой, отдельно дублировать не нужно.

Переключатель «Списком/Свайпами» (`<div className="mb-4 flex gap-2">...`)
в этом состоянии **не рендерится вовсе** (не просто скрыт стилем) — иначе
он остаётся в DOM за фиксированным оверлеем и ловит фокус клавиатурой или
скринридером, оставаясь недоступным глазами, но доступным раскладкой
табуляции.

Блок сетки (`grid gap-5 ...`) уже и так не рендерится при `mode ===
"swipe"` — без изменений.

### Выход из режима

Три пути приводят к одному результату — `setModeOverride("grid")` (то же
состояние, что переключает кнопка «Списком»):

1. Клик по «✕».
2. Системная кнопка/жест «назад» на телефоне.
3. (Пере)вход в grid-режим любым другим существующим путём не меняется.

Технически оба входа (1) и (2) идут через один и тот же путь, чтобы не
было расхождения в истории браузера:

```tsx
useEffect(() => {
  if (!focusMode) return;
  window.history.pushState({ unionFocusMode: true }, "");
  const onPopState = () => setModeOverride("grid");
  window.addEventListener("popstate", onPopState);
  return () => window.removeEventListener("popstate", onPopState);
}, [focusMode]);

function exitFocusMode() {
  // history.back() запускает popstate-обработчик выше, который и
  // переключает mode на "grid" — так «✕» не создаёт отдельный путь смены
  // состояния и не оставляет висящую запись в истории, съедающую лишний
  // «назад» после закрытия кнопкой, а не жестом.
  window.history.back();
}
```

При входе в `focusMode` (переключении на мобильный свайп) пушится одна
запись истории; клик «✕» или системное «назад» её выталкивает, что и
приводит к `popstate` → `mode = "grid"`. Второе нажатие «назад» после
выхода ведёт себя как обычно (уходит со страницы), а не остаётся «съеденным».

### Блокировка скролла фона

Пока оверлей открыт, `document.body` получает `overflow: hidden` — на iOS
Safari `position: fixed`-блок не мешает странице позади скроллиться через
тач без этого:

```tsx
useEffect(() => {
  if (!focusMode) return;
  const previous = document.body.style.overflow;
  document.body.style.overflow = "hidden";
  return () => {
    document.body.style.overflow = previous;
  };
}, [focusMode]);
```

## Не в объёме этой задачи

- Fullscreen API браузера (`element.requestFullscreen()`) — не используется:
  ненадёжен на iOS Safari (не поддерживает для произвольных элементов, кроме
  видео). Оверлей полностью решает задачу средствами CSS/JS без него.
- Десктопный свайп-режим — не меняется.
- Отдельный URL/роут для фокус-режима — сознательно отклонённый вариант
  (см. обсуждение вариантов A/B/C перед этой спекой), не реализуется.

## Тестирование

Автотестов для `recommendations-view.tsx` в проекте нет (как и для
`recommendation-filters.tsx` до этого) — это существующий паттерн для
UI-обвязки в Union, не пробел, вносимый этой задачей.

Ручная проверка через dev-сервер (resize браузера в мобильную ширину,
`preview_start` + `resize_window`/`preset: mobile`, залогиниться dev-
аккаунтом):

- На мобильной ширине `/union/recommendations` сразу открывается в
  полноэкранном свайп-виде: не видно шапки портала, `UnionTopBar`,
  фильтров, счётчика «Найдено», переключателя «Списком/Свайпами» и
  нижнего таб-бара.
- Кнопка «✕» видна, с отступом от верхнего края под чёлку/статус-бар.
- Свайп/лайк/пропуск/буст/undo работают как раньше.
- Клик «✕» возвращает к обычной странице со списком (`mode: "grid"`),
  вся обвязка снова видна.
- Кнопка браузера/жест «назад» (эмулируется через `navigate({url: "back"})`
  или `computer` history back) при открытом фокус-режиме тоже возвращает
  к списку, не уводя со страницы; повторное «назад» после этого уходит со
  страницы обычным образом.
- На десктопной ширине переключение на «Свайпами» остаётся как сейчас —
  инлайн, без полноэкранного оверлея, вся обвязка страницы видна.
