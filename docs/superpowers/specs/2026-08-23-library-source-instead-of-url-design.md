# Материал без ссылки: источник вместо адреса

Дата: 2026-08-23

## Задача

Не у каждого материала есть адрес в интернете. Цитата из книги, бумажное
издание, запись лекции без публикации — их место в справочнике описывается
не ссылкой, а источником: «Бхагавад-гита 9.22, комментарий Прабхупады».
У видео и сайтов ссылка, наоборот, обязательна.

## Решения

**Ссылка или источник — переключатель, не тип.** «Книга» бывает и бумажной,
и на сайте; «статья» — и в журнале, и в блоге. Жёсткая привязка «тип →
ссылка или источник» врала бы. Переключатель «есть ссылка / только
источник» доступен при любом типе, а тип задаёт лишь его начальное
положение: `book` → источник, все остальные → ссылка.

**Источник — одна свободная строка.** Структура «издание + место» точнее
для группировки, но требует дисциплины от заполняющего и множит поля в
режиме, который существует ради простоты. Свободная строка покрывает и
«Бхагавад-гита 9.22», и «Лекция во Вриндаване, 1974».

**Тип переезжает на первый шаг мастера.** От него зависит, что показывать
на следующем шаге, поэтому спрашивать адрес раньше типа больше нельзя. Это
чинит и логическую странность прежнего порядка: «что вы добавляете»
уместнее «дайте адрес».

## Данные

`apps/api/prisma/schema.prisma`, модель `LibraryEntry`:

- `url String` → `String?`
- `urlNormalized String @unique` → `String? @unique`
- `domain String` → `String?`
- новое поле `source String?`

NULL-ы в Postgres не конфликтуют между собой, поэтому `@unique` на
`urlNormalized` продолжает ловить дубли ссылок и не мешает записям без
адреса.

Инвариант «заполнено хотя бы одно из двух» кладётся CHECK-constraint'ом в
миграцию — Prisma такое не выражает, а сервис может однажды разойтись с
реальностью:

```sql
ALTER TABLE "LibraryEntry" ADD CONSTRAINT "LibraryEntry_url_or_source"
  CHECK ("url" IS NOT NULL OR "source" IS NOT NULL);
```

Существующие строки все с `url NOT NULL`, ограничение выполнимо сразу.

В `LibraryEnrichmentStatus` добавляется `not_applicable`. Без него записи
без ссылки навсегда зависли бы в `pending` и попали в админскую плитку
«Без обогащения» как проблемные, хотя обогащать у них нечего.

### Дедупликация

По ссылке остаётся как есть. Для источника её нет и не будет: unique на
текстовый источник неверен по смыслу — «Бхагавад-гита» законно стоит
источником у полусотни разных материалов.

## Мастер (простой режим) — четыре шага

1. **Что добавляем** — тип материала и язык.
2. **Где найти и как называется** — переключатель, под ним поле ссылки
   либо поле источника, и название. (На прежнем шаге 2 тоже было два поля,
   так что это не усложнение.)
3. **Раздел и категории** — без изменений.
4. **Проверка** — сводка, необязательное описание, отправка.

Шаг 2 считается готовым, когда заполнены название и то из двух полей,
которое выбрано переключателем.

## Форма «профи»

Тот же переключатель и поле источника рядом с полем ссылки. Остальное без
изменений.

## Карточка записи

Кнопка «Открыть» рисуется только при наличии ссылки. Для записи с
источником вместо неё — строка «Источник: …». Превью-скриншот и обогащение
OG-тегами для таких записей не запускаются, статус сразу
`not_applicable`. Фильтр по домену их не находит — ожидаемо, домена нет.

## Тестирование

- `entry-draft.spec.ts` — правило «ссылка или источник», готовность нового
  шага 2 в обоих положениях переключателя, умолчание переключателя по типу.
- `add-entry-wizard.spec.tsx` — переключатель меняет поле; с источником
  мастер доходит до отправки без ссылки.
- `library-entries.service.spec.ts` — создание с источником без ссылки,
  отказ, когда пусты оба поля.

## Вне рамок

- Структурированный источник (издание + место отдельными полями).
- Поиск и группировка по источнику.
- Перенос уже добавленных ссылок в источники.
