# Редизайн админки Motivation

Дата: 2026-08-16

## Проблема

Страница `/admin/motivation` — одна длинная простыня: списки авторов, источники,
форма ручного добавления и две очереди модерации идут подряд в одном столбце.
Конкретно:

- Добавить цитату вручную нельзя без пяти заполненных полей — обязательны
  произведение, глава/стих и контекст (`motivation.service.ts`, `addManualQuote`).
- Категорию поста выбрать негде: `motivation-copy.service.ts` жёстко проставляет
  `'verified_quote'`, менять можно только PATCH-запросом.
- Пояснение, сгенерированное нейросетью, показывается целиком и в админке,
  и в карточке ленты — читать очередь приходится сквозь простыни текста.
- С телефона форма непригодна: поля с `text-sm` (14px) заставляют iOS Safari
  зумить страницу при фокусе, ряды кнопок разъезжаются через `flex-wrap`.
- `motivation-admin-controls.tsx` — 450 строк, держит в себе четыре разные
  обязанности сразу.

## Решение

### Навигация: вложенные роуты

Таб-бар живёт в `apps/web/src/app/admin/motivation/layout.tsx`, каждая вкладка —
свой серверный компонент, грузящий только свои данные:

| URL | Содержимое |
| --- | --- |
| `/admin/motivation/queue` | Очередь модерации (тексты + изображения) |
| `/admin/motivation/add` | Ручное добавление цитаты |
| `/admin/motivation/search` | Авторы и источники для автопоиска |
| `/admin/motivation/categories` | Справочник категорий |

`/admin/motivation` редиректит на `/queue`.

Сейчас страница на каждый заход делает четыре запроса разом; после разделения
вкладка «Добавить» не ждёт список постов. Настоящие URL дают рабочую кнопку
«назад» и возможность кинуть ссылку на конкретный раздел.

Отвергнуто: `?tab=` (страница остаётся точкой, куда всё стекается) и клиентские
табы (грузят все данные всегда — худший вариант на мобильном).

### Категории: справочник-таблица, слаг в посте

```prisma
model MotivationCategory {
  id        String   @id @default(uuid())
  slug      String   @unique
  title     String
  sortOrder Int      @default(0)
  isDefault Boolean  @default(false)
  parentId  String?  // self-relation, ON DELETE SET NULL
}
```

Вложенность ровно в два уровня: у категории верхнего уровня `parentId` пустой,
у подкатегории указывает на неё. Третий уровень сервис отклоняет — дерево
произвольной глубины в селекте выбора нечитаемо, а обходить его при каждом
рендере дороже, чем одна группировка.

Слаги остаются плоскими и глобально уникальными: пост хранит слаг листа, так
что префикс родителя ничего не добавил бы, кроме длины.

`MotivationPost.category` остаётся строкой и хранит слаг. Существующий индекс
`@@index([category, status, publishedAt])` и фильтр ленты `?category=`
продолжают работать без изменений; старые записи со значением `verified_quote`
не ломаются — под них миграция заводит строку справочника.

Отвергнут FK `categoryId`: нормализация «правильнее», но требует бэкфила всех
постов, правки запросов ленты и индекса — для десятка категорий выгоды нет.

Правила:

- Слаг генерируется из названия транслитерацией. По контракту сервисного модуля
  хелпер дублируется внутрь модуля (`motivation/category-slug.ts`), а не
  импортируется из `library/`.
- Ровно одна категория помечена `isDefault`. Её слаг проставляет
  `motivation-copy.service.ts` вместо захардкоженного `'verified_quote'`.
  Установка флага другой категории снимает его с прежней в одной транзакции.
- Дефолтную категорию удалить нельзя. При удалении обычной посты не трогаются —
  остаются со старым слагом, который просто пропадает из селекта.
- При удалении родителя подкатегории всплывают на верхний уровень
  (`ON DELETE SET NULL`), а не исчезают вместе с ним: одно нажатие не должно
  уносить целую ветку.
- Нельзя вложить категорию, у которой уже есть свои подкатегории, — иначе
  появился бы третий уровень.
- В селекте выбора подкатегории идут `<optgroup>` своего родителя; сам родитель
  остаётся выбираемым пунктом «— без подкатегории».

### Ручное добавление: два обязательных поля

Обязательны только **текст цитаты** и **автор**. Язык определяется по алфавиту
(кириллица → `ru`, деванагари → `hi`, иначе `en`) и переключается вручную.
Категория — селект из справочника. Произведение, глава/стих, контекст и ссылка
уезжают в свёрнутый блок «Уточнить источник».

Бэкенд: `addManualQuote` снимает обязательность с `work`, `locator`,
`contextExcerpt`. **Колонки в БД остаются `NOT NULL`** — пишется пустая строка.
Так не нужна миграция и не ломаются существующие читатели. Места, где атрибуция
склеивается через ` · `, отфильтровывают пустые части, иначе выйдет
«Прабхупада ·  · ».

Известный компромисс: `contextExcerpt` уходит в промпт
`generateVerifiedQuoteCopy`. Без него нейросеть пишет пояснение только по самой
цитате — качество ниже. Поле остаётся в форме, просто не блокирует отправку.

### Сворачиваемые пояснения

Общий компонент `collapsible-block.tsx` на `<details>` — работает без JS и с
клавиатуры. В свёрнутом виде показывает первые строки и «Развернуть».

- Админка: «Пояснение VedaMatch», «Контекст», «Промпт изображения» свёрнуты по
  умолчанию.
- Лента (`motivation-post-card.tsx`): цитата и атрибуция видны всегда, пояснение
  под «Пояснение ▾».

`post.text` склеен как `цитата\n\nпояснение`, поэтому текст режется по первому
пустому абзацу: первый — цитата, остальное — пояснение. В админской карточке это
заодно убирает дублирование цитаты, которая уже показана выше в блоке оригинала.

### Мобильная версия

- Все `input` / `textarea` / `select` получают `text-base` (16px) — иначе iOS
  Safari зумит страницу при фокусе. Это главная причина, почему форма
  «неудобная» с телефона.
- Таб-бар — горизонтальный скролл со `snap`.
- Кнопки действий в карточке очереди: на мобиле липкая панель внизу, полная
  ширина, тап-цель ≥ 44px. «Отклонить» убирается под «Ещё», чтобы не жать
  случайно.
- Строки списков авторов и источников: имя сверху, кнопки под ним в ряд, вместо
  разъезжающегося `flex-wrap`.
- Отступы карточек `p-4 sm:p-5`, сетка изображений `lg:grid-cols-2`.

## Тесты

`motivation-admin-controls.spec.tsx` и `manual-quote-form.spec.tsx` завязаны на
текущую разметку — свёрнутые блоки и разъезд по вкладкам их ломают. Оба
обновляются. Добавляются:

- отправка формы с двумя заполненными полями и пустым источником;
- автоопределение языка по алфавиту;
- CRUD категорий: создание генерирует слаг, дефолтная не удаляется, смена
  дефолта снимает флаг с прежней;
- `addManualQuote` пишет пустые строки вместо отсутствующих полей.

## Вне объёма

Фильтр ленты по категории на публичной стороне. API (`?category=`) это уже
поддерживает, но UI-фильтр не входит в эту итерацию.
