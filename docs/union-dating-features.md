# Знакомства: свайпы, лайки, буст

План развития модуля `union` до уровня привычных приложений знакомств
(референс — скриншоты VK Знакомств). Документ описывает, что добавляем,
в каком порядке и какие решения уже приняты.

## Принятые решения

1. **Бета — всё бесплатно.** Суперлайк, буст и откат свайпа работают без оплаты.
   Лимиты и цены не удаляем, а выносим в один конфиг `union-limits.ts`, где на
   время беты стоит режим `beta` (щедрые квоты, без списаний). Переход на платную
   модель — смена констант плюс проверка подписки через `billing`, без переписывания
   сервисов.
2. **Гибридный мэтчинг.** Текущая модель «заявка + подтверждение» — надмножество
   тиндер-логики, поэтому оба режима живут в одном коде:
   - взаимный лайк → заявка сразу `accepted`, чат открыт, подтверждать нечего;
   - односторонний лайк → заявка `pending`, видна получателю в «Лайках»;
   - в анкете появляется настройка «Кто может со мной связаться»:
     `requests` (по умолчанию, гибрид) или `mutual_only` (строгий режим —
     односторонние заявки не показываются и чат открывает только взаимный лайк).
     Настройка соседствует с существующей `requestsFromVerifiedOnly`.
3. **«Подборки» — пресеты фильтров** поверх текущего `getRecommendations`:
   «Рядом», «Новые», «Высокая совместимость», «Подтверждённые преданные».
   Отдельной логики выдачи и ежедневных лимитов не делаем; «Новые» и «Высокая
   совместимость» потребовали только двух параметров запроса — `sort` и
   `minScore`.

## Этап 1. Фундамент: решения по свайпам — сделано

Как получилось в коде:

- `UnionSwipe` + enum `UnionSwipeDecision`, `UnionContactMode` на `UnionProfile`
  (миграция `20260807000000_union_swipes`, накатана вручную через
  `migrate deploy` — `migrate dev` требовал ресета базы из-за дрейфа в
  `20260729131836_user_gender`).
- `union-swipe.service.ts` + `union-swipe.controller.ts`:
  `POST /union/swipes`, `DELETE /union/swipes/last`.
- Лайк — источник правды об интересе; заявка создаётся по нему. Взаимный лайк
  проходит через существующую логику встречной заявки и сразу становится
  `accepted`. Если встречной заявки нет (лайк был в строгом режиме), она
  заводится от того, кто лайкнул первым.
- `contactMode: mutual_only` проверяется и в `UnionConnectionService.create`,
  поэтому прямой POST заявки в обход колоды тоже не пройдёт без взаимности.
- Свайпнутые исключены из `getRecommendations`; откатанные (`undoneAt`)
  возвращаются в выдачу.
- Колода шлёт решения на сервер, есть кнопка отката ↺ и сообщение «Взаимно!
  Чат открыт» при мэтче. В анкете — селект «Кто может со мной связаться».
- Тесты: `union-swipe.service.spec.ts` (11 кейсов), 89 тестов Union зелёные.

Исходный замысел этапа:

- Prisma:
  ```
  enum UnionSwipeDecision { like superlike pass }

  model UnionSwipe {
    id         String
    fromUserId String
    toUserId   String
    decision   UnionSwipeDecision
    createdAt  DateTime
    undoneAt   DateTime?
    @@unique([fromUserId, toUserId])
    @@index([toUserId, decision])
  }
  ```
- `union-swipe.service.ts`: идемпотентная запись решения, исключение уже
  свайпнутых из выдачи в `union-profile.service.ts` / `union-matching.service.ts`.
- `like` / `superlike` создают `UnionSwipe` **и** `UnionConnectionRequest`.
  Встречный лайк → заявка `accepted` (авто-мэтч), иначе `pending`.
- Настройка `contactMode: requests | mutual_only` в `UnionProfile`.
- Эндпоинты: `POST /union/swipes`, `DELETE /union/swipes/last`.
- Тесты: `union-swipe.service.spec.ts`, дополнить `union-matching.service.spec.ts`
  (свайпнутые не возвращаются, авто-мэтч при встречном лайке, `mutual_only`
  прячет односторонние заявки).

## Этап 3. Суперлайк (🔥) — сделано

- `decision: superlike` + `isSuperlike` на `UnionConnectionRequest`
  (миграция `20260807010000_union_superlike`). Входящие сортируются суперлайками
  вперёд и в запросе к базе, и в панели «Лайки»; карточка получает рамку и
  плашку «🔥 Суперлайк».
- Квота `SUPERLIKES_PER_DAY` проверяется в `UnionSwipeService`, до записи свайпа.
- Третья кнопка в ряду действий и свайп вверх по карточке с меткой «СУПЕРЛАЙК».

## Лимиты

`union-limits.ts` — единственное место с числами. `UNION_LIMITS_MODE = 'beta'`:
суперлайков 20/сутки, откатов 50/сутки, буст 40 минут. Переключение на `paid`
меняет квоты; проверку подписки через `billing` добавлять там же.

## Этап 4. Буст «Внимание» (⚡) — сделано

- Prisma: `UnionBoost { userId, startedAt, expiresAt }`, миграция
  `20260807020000_union_boost`. Длительность — `BOOST_DURATION_MS` (40 минут)
  в `union-limits.ts`. Поле `source` не заводил: пока буст один и бесплатный,
  различать источники нечего — добавится вместе с оплатой.
- `getRecommendations` поднимает бустнутых в начало выдачи, до сортировки
  по совместимости.
- `POST /union/boost`, `GET /union/boost/status`. Второй буст поверх активного
  не запускается.
- UI: `union-boost-button.tsx` — кнопка ⚡ в правом верхнем углу карточки,
  модалка со скрина («Внимание», пояснение, «Активировать внимание»), после
  активации на кнопке идёт обратный отсчёт мм:сс. Статус тянется с сервера,
  поэтому таймер переживает перезагрузку страницы.

## Этап 6. Нижняя навигация, «Лайки», «Подборки»

Сделано (без изменений API, на существующих данных):

- `union-tabbar.tsx` — пять вкладок, фиксирован снизу, только на мобильных;
  `UnionNav` спрятан за `md:` и остаётся десктопной навигацией.
- `union-top-bar.tsx` — мобильный заголовок раздела с кнопкой настроек справа,
  ведёт в редактирование анкеты `/union/profile`.
- `/union/likes` — входящие лайки, ответ «взаимность / пропустить» на месте.
- `/union/chats` — список диалогов, строится из принятых заявок.
- `/union/collections` — пресеты фильтров из решения №3.

Дополнено позже:

- Суперлайки в «Лайках» идут сверху и с подсветкой (этап 3).
- `readAt` на `UnionChatMessage` (миграция `20260807030000_union_chat_read_at`)
  и `GET /union/chats`: список диалогов отдаёт превью последнего сообщения и
  счётчик непрочитанного, открытие чата помечает входящие прочитанными.
  Точка на вкладке «Чаты» и бейджи в списке работают от этих данных.

- Подборки «Новые» (`sort=new`) и «Высокая совместимость» (`minScore=70`):
  в `UnionRecommendationFilters` добавлены `sort: 'match' | 'new'` и `minScore`.
  Сортировка по свежести идёт после подъёма бустом, порог отсекает анкеты до
  пагинации. Фильтры на странице рекомендаций сохраняют оба параметра скрытыми
  полями, чтобы подборка не сбрасывалась при уточнении поиска.
