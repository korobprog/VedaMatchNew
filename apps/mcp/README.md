# MCP-сервер VedaMatch

Даёт ассистенту (Claude Code, Claude Desktop) доступ к сервису «Работа»:
рабочие среды, доски, карточки, сроки. Сервер ходит в портальный HTTP-API под
**персональным ключом** — своим у каждого человека, поэтому напарник, подключив
свой Claude, видит ровно те среды, где состоит сам, и действует от своего
имени.

## Что умеет

| Инструмент          | Что делает                                            |
| ------------------- | ----------------------------------------------------- |
| `work_list_spaces`  | Список рабочих сред                                    |
| `work_get_space`    | Среда целиком: доски, участники, роли                  |
| `work_get_board`    | Доска: колонки, карточки, исполнители, сроки           |
| `work_get_task`     | Карточка: описание, чек-лист, комментарии, история     |
| `work_get_agenda`   | «Мой день»: сроки по всем средам сразу                 |
| `work_create_task`  | Завести задачу на доске                                |
| `work_update_task`  | Изменить название, срок, исполнителя, важность         |
| `work_move_task`    | Перенести карточку в другую колонку                    |
| `work_comment_task` | Написать комментарий в карточку                        |

Удаления, архива, приглашений и работы с файлами здесь намеренно нет: доска
общая, а ошибка модели дешевле, когда её нечем стереть. Набор расширяется по
мере того, как в работе выясняется, чего не хватает.

## Как подключить

### 1. Выпустить ключ

В портале: **Профиль → Ключи доступа**. Назовите ключ так, чтобы через полгода
понять, чей он («Claude на ноутбуке»), и выберите права:

- `work:read` — только смотреть;
- `work:write` — ещё и менять (включает чтение).

Ключ показывается **один раз**: в базе хранится только его отпечаток.

### 2. Собрать сервер

```bash
pnpm --filter @vedamatch/mcp build
```

### 3. Прописать в клиенте

Claude Code — `.mcp.json` в проекте или `claude mcp add`:

```json
{
  "mcpServers": {
    "vedamatch": {
      "command": "node",
      "args": ["<путь к репозиторию>/apps/mcp/dist/index.js"],
      "env": {
        "VEDAMATCH_API_KEY": "vm_…",
        "VEDAMATCH_API_URL": "https://vedamatch.ru/api"
      }
    }
  }
}
```

`VEDAMATCH_API_URL` необязателен: без него сервер идёт в `http://localhost:4000`
— то, что нужно при локальной разработке.

## Как проверить, что работает

Спросите ассистента: «покажи мои рабочие среды». Должен ответить списком.
Если нет — смотрите текст ошибки, он написан как инструкция:

- **«Не задан VEDAMATCH_API_KEY»** — клиент не передал переменную окружения;
- **«не похож на ключ портала»** — вписан токен из браузера, он живёт минуты;
- **«Ключу не хватает права…»** — ключ выпущен только на чтение, нужен новый с
  `work:write`;
- **«Портал не принял ключ»** — ключ отозван или просрочен.

## Устройство

Сервер ходит в портал по HTTP, а не в базу напрямую, и это главное решение
здесь. Все проверки прав — членство в среде, роль, доступ к доске — уже живут в
контроллерах «Работы» и применяются сами. Клиент, знающий про Prisma, пришлось
бы учить тем же правилам заново, и однажды они разошлись бы с настоящими.

Права ключа проверяются в `AuthGuard` портала по двум признакам: первый сегмент
пути (он же slug сервиса) и HTTP-метод. Поэтому ключ `work:read` не создаст
задачу и не заглянет в «Общение», даже если там появятся новые маршруты.
